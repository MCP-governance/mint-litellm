# 개발 환경과 고정값

## 의존성 잠금

- 판본은 `uv.lock`이 고정한다. `pyproject.toml`에는 범위만 적고, 잠금 파일은 리눅스에서 만든다.
- 설치: `uv sync --locked --extra dev --extra litellm` (잠금과 `pyproject.toml`이 어긋나면 실패한다).
- 의존성을 바꾸면 `uv lock`으로 잠금을 다시 만들어 함께 커밋한다. 일부만 올릴 때는 `uv lock --upgrade-package <이름>`.
- CI는 `uv lock --check`로 잠금이 최신인지 먼저 확인한다.

## 이미지 고정

compose, Dockerfile, 시험 코드, CI 서비스에 쓰는 모든 이미지는 `이름:태그@sha256:<다이제스트>`로 쓴다. 대상은 PostgreSQL, 정책 엔진(OPA), LiteLLM, 파생 이미지의 Python 기본 이미지다.

갱신 순서:

1. 새 태그의 다이제스트를 레지스트리에서 조회한다: `docker buildx imagetools inspect <이름>:<태그>`의 `Digest` 줄(다중 플랫폼 이미지는 인덱스 다이제스트).
2. 같은 이미지를 쓰는 모든 곳을 함께 바꾼다. `git grep -n "sha256:"`로 위치를 찾는다. OPA는 `deploy/compose.yaml`, `deploy/Dockerfile.litellm`, `tests/unit/policy`의 두 시험이 같은 값을 쓴다. PostgreSQL은 `deploy/compose.yaml`과 `.github/workflows/ci.yml`이 같은 값을 쓴다.
3. 전체 시험과 `deploy/mint.sh up`으로 기동을 확인한다.

## CI 액션 고정

`.github/workflows/ci.yml`의 액션은 태그가 아니라 커밋 SHA로 쓰고, 뒤에 판본을 주석으로 적는다. 갱신할 때는 새 판본 태그가 가리키는 커밋 SHA를 조회해(`gh api repos/<소유자>/<저장소>/git/ref/tags/<태그>`, 주석 태그면 한 번 더 따라간다) 둘 다 바꾼다.

## 이미지 안 의존성

`deploy/constraints.txt`는 `uv.lock`에서 내보낸 판본 제약이고 파생 이미지가 `pip install -c`로 쓴다(제어 평면 이미지도 같은 이미지다). 의존성을 바꿔 `uv lock`을 다시 했으면 다음으로 다시 만들어 함께 커밋한다. CI는 같은 명령의 결과가 커밋된 파일과 같은지 확인한다.

```
uv export --frozen --no-dev --extra litellm --format requirements-txt --no-hashes --no-emit-project -o deploy/constraints.txt
```
